# 2026-11-26 구현과 검증 기록 (KST)

## 채택한 요구사항

- 저메모리 macOS 네이티브 CLI를 우선하며 Electron과 외부 런타임을 사용하지 않는다.
- Core Audio Process Tap으로 시스템 오디오를 캡처하고 캡처 중 원래 출력을 음소거한다.
- UDP raw PCM S16LE, 48kHz, stereo로 FFplay와 호환한다.
- 후속 메뉴바 UI가 재사용할 수 있도록 Session에서 리소스와 스레드 수명을 소유한다.
- 코드 스타일·기록·검증 절차는 저장소의 AGENTS.md와 coding-style 문서를 따른다.

## 구현과 리뷰

- C++20/Objective-C++, Apple 기본 프레임워크, CMake로 구현했다.
- HAL 콜백은 고정 용량 SPSC 링에 복사만 한다. 변환과 비차단 UDP 송신은 별도 스레드에서 처리한다.
- 입력 포맷 검증, planar 복사, 입력 고갈 시 변환 상태 유지, 적체 상한, 종료 시 RAII 정리를 검토했다.
- macOS 14.2 호환성을 위해 CLI 부동소수점 파싱에 classic-locale 스트림을 사용한다.

## 확인된 검증

- macOS Release 빌드, formatter, 서명 검사, 코어/UDP CTest 2개를 통과했다.
- 링 순서·경계·동시성, 인자 오류, 44.1/48/96kHz 연속 리샘플링을 확인했다.
- IPv4/IPv6 loopback, 64/1024/1400바이트 패킷, 주파수·진폭·좌우 샘플, SIGINT/SIGTERM 종료를 확인했다.
- 권한 승인 후 실제 afplay → Process Tap → PCM → localhost UDP 테스트에서 좌우 알려진 주파수를 검출했다.
  6초 동안 1122패킷을 보냈고 입력·UDP 드롭과 오버런은 0이었다.
- 원래 출력을 유지한 10초 캡처/송신 프로파일의 RSS는 16.23~16.38MiB, CPU는 1.3~1.6%였다.
  이는 짧은 환경별 관찰값이며 장기 성능 보장이 아니다.
- 내장 스피커 출력 장치와 BlackHole 미사용 구성에서도 동작이 보고됐다.
- 시스템 출력 볼륨을 바꿔도 캡처 신호 크기가 유지되는 현상이 보고됐다. 모든 장치·OS의 보장으로 확대하지 않는다.

## 후속 관찰

- 간헐적 소리 튐이 보고됐지만 이후 재현되지 않아 설정을 유지하고 관찰하기로 했다.
- SoX의 --buffer 증가는 내부 처리 버퍼 조정이며 UDP 패킷 크기 변경과 구별한다.
- 송신 드롭 통계는 네트워크 중간 손실과 수신기 underrun을 검출하지 못한다.
- 물리적 음소거/복구의 개별 청취, 장시간 클럭 차이·누수·배터리·종단 지연은 별도 검증이 필요하다.

## 공개 저장소 개인정보 정리

- 원격 이력 교체를 포함한 개인정보 정리가 승인됐다.
- 개인 이메일·사용자 홈 경로·실제 LAN 주소·채팅 식별자·개인 대화 서술을 공개 파일에서 제거한다.
- 기본 목적지는 localhost, 문서의 원격 예시는 문서용 예약 주소로 바꾼다.
  실제 수신 주소는 사용자가 실행할 때 명시한다.
- 커밋 작성자·커미터는 공개 GitHub 계정명과 GitHub noreply 이메일을 사용한다.
  저장소에 실제 개인정보를 다시 적거나 이전 커밋을 백업 브랜치·태그로 올리지 않는다.
- 코드 리뷰 후 formatter·빌드·자동 테스트를 실행하며 실제 캡처를 추가로 시작하지 않는다.
- 강제 갱신은 이전 원격 SHA를 조건으로 제한한다. 원격 main 이력과 게시 파일을 다시 점검한다.
- 정리 후 개인정보 패턴 검사에서 개인 이메일·홈 경로·LAN 주소·채팅 ID·인증키 패턴은 검출되지 않았다.
- Release 재빌드, formatter, 코어/UDP CTest 2개를 통과했다.
